# Architecture Decision Records (ADRs)

## ADR-001: Frappe & ERPNext Version 16 Stack Pinning
- **Status:** Accepted
- **Context:** Need long-term stable, modern foundation for Indian School ERP.
- **Decision:** Target `version-16` across frappe, erpnext, education, hrms, payments, and india-compliance.
- **Consequences:** Modern Python 3.12+ features, Frappe UI v16 improvements, stable upstream maintenance.

## ADR-002: Multi-Tenancy Architecture (One Site Per School)
- **Status:** Accepted
- **Context:** Schools require strict data isolation, distinct academic calendars, custom fee heads, and independent audit trails.
- **Decision:** Deploy one Frappe site per school (`school_code.school-os.local`) on a shared bench rather than multi-company shared database.
- **Consequences:** Complete physical DB isolation, safe backups, zero risk of cross-school data leak.

## ADR-003: Headless Core with Custom Consumer Frontend
- **Status:** Accepted
- **Context:** Frappe Desk is powerful for administrators but too complex for teachers, parents, and students.
- **Decision:** Keep Frappe Desk as backend administration; build modern React/Tailwind/shadcn frontend for role-specific user journeys.
- **Consequences:** Consumer-grade UX, high adoption, rapid mobile entry.

## ADR-004: Upstream Preservation & Clean Custom Extension
- **Status:** Accepted
- **Context:** Upstream Frappe/ERPNext/Education repositories receive ongoing bug fixes and security patches.
- **Decision:** Never fork or monkey-patch core doctypes directly in upstream repos. Implement all Indian localization inside `school_india`.
- **Consequences:** Smooth upgrades without merge conflicts.

## ADR-005: Workflow Ingestion from Gibbon and openSIS
- **Status:** Accepted
- **Context:** Frappe Education lacks Indian examination patterns (CCE, FA/SA) and advanced timetable substitution engines.
- **Decision:** Use Gibbon for timetable/substitution workflow design and openSIS for grading/transcript design, reimplemented natively in Frappe.
- **Consequences:** Avoids Frankenstein PHP/Python bridges while capturing battle-tested SIS capabilities.
